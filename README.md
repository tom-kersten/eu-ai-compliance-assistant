# EU AI Compliance Assistant

## What and why

A Dutch-language assistant that answers questions about four EU legal texts: the
AI-verordening, the AVG, the CRA, and the Digitale omnibus inzake AI. It is meant
for product owners, engineers, and compliance leads at companies that build or
run AI applications.

Every answer is grounded in the legal text and cites the provisions it relies on,
which you can expand to read in full. When your situation is unclear,
the assistant asks a clarifying question first. When the corpus does not cover a
question, it says so instead of guessing. It explains provisions and points to
the source; whether you comply remains your decision.

It runs with a hosted model through OpenRouter, or fully self-hosted with vLLM.

## Quickstart (online)

1. Copy the example env and set keys:

   ```bash
   cp .env.example .env
   # edit .env and set LLM_API_KEY and EMBEDDING_API_KEY
   ```

2. Start the online stack:

   ```bash
   make up
   ```

3. Ingest the corpus (once):

   ```bash
   make ingest
   ```

4. Open the frontend at <http://localhost:8501>. Backend health is at
   <http://localhost:8000/health>.

5. Run the evaluation:

   ```bash
   make eval
   ```

Everything runs in Docker. No host Python environment is needed. Run `make help`
for the full list of targets.

## Quickstart (offline)

Self-hosted vLLM. Hardware, quantization, and verified flags are in
[docs/OFFLINE.md](docs/OFFLINE.md).

```bash
cp .env.offline.example .env.offline
# edit .env.offline to match your hardware and models
make up-offline
make ingest ENV_FILE=.env.offline
make test-live ENV_FILE=.env.offline
```

## Architecture

```
Browser -> Streamlit frontend (8501)
        -> FastAPI backend (8000) -> Postgres + pgvector
                                  -> Embedding endpoint (hosted or vLLM)
                                  -> LLM endpoint (hosted or vLLM)
```

The backend streams progress to the frontend as Server-Sent Events. Details:
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Scope and behavior:
[docs/REFERENCE.md](docs/REFERENCE.md). Prompt requirements:
[docs/PROMPT_SPEC.md](docs/PROMPT_SPEC.md).

## Design decisions and trade-offs

- Stateless backend; session state lives in the Streamlit frontend.
- Postgres with pgvector, exact cosine search, fixed embedding dimension (2000).
- Two LLM calls per question maximum: selection (one call) and answer (one call).
- Prompts written in English; UI and outputs in Dutch.
- No third-party orchestration frameworks; small, testable functions.
- Provider behavior is verified against the live API before it is coded against
  ([docs/PROVIDER_NOTES.md](docs/PROVIDER_NOTES.md), regenerated by
  `make verify-providers`).

## Known limitations

- Single-turn evaluation set only; multi-turn behavior is not fully validated.
- The retrieval threshold was tuned on a small eval set; some misses remain
  (notably Q06–Q08 retrieval gaps recorded in the eval reports).
- LLM output is not deterministic, so individual eval questions can flip between
  runs (Q05 and Q08 in particular; see the eval report).
- Offline (vLLM) profile is documented but unverified without GPU hardware.
- The corpus is not a consolidated single document; provenance and versioning
  are manual via the manifest.

## Roadmap

- Consolidate and version the legal texts; sign each snapshot.
- Add reranking or a hybrid sparse + dense retrieval layer.
- Multi-turn evaluation and user studies for clarifying questions.
- Persistence, authentication, and observability for production APIs.

## Corpus and sources

The legal texts in `corpus/raw/` are the Dutch-language versions published on
[EUR-Lex](https://eur-lex.europa.eu/), © European Union, 1998–2026, reused under
Commission Decision 2011/833/EU:

| Document | Version used |
|---|---|
| AI-verordening, Verordening (EU) 2024/1689 | Consolidated text of 27 July 2026 |
| AVG, Verordening (EU) 2016/679 | Consolidated text of 4 May 2016 |
| CRA, Verordening (EU) 2024/2847 | Consolidated text of 20 November 2024 |
| Digitale omnibus inzake AI, Verordening (EU) 2026/1744 | Official Journal text (recitals and Article 4) |

Only the texts published in the Official Journal of the European Union are
authentic. Consolidated versions are documentation tools. Ingestion changes only
whitespace and removes amendment markers; the wording is never edited.
`corpus/manifest.yaml` lists which file and which parts are indexed.

The MIT license in `LICENSE` covers the code and documentation in this
repository, not the legal texts.

## How it was built

The project was built with AI coding agents (Cursor and Claude Code), working
test-first from the design documents in `docs/`: one task at a time from
[docs/IMPLEMENTATION_PLAN.md](docs/IMPLEMENTATION_PLAN.md), with the rules in
[AGENTS.md](AGENTS.md) and `.cursor/rules/`.

## Tests and continuous integration

These need no keys or GPUs:

```bash
make lint            # ruff check and format check (backend, eval, frontend)
make test            # backend unit, api, and db suites
make test-frontend   # frontend suite
```

Opt-in, against real providers (needs keys, costs money):

```bash
make test-live
make eval
```

GitHub Actions runs `make lint`, `make test`, and `make test-frontend` on every
push and pull request, and validates the compose file for both profiles. See
[.github/workflows/ci.yml](.github/workflows/ci.yml). Evaluation reports are
written to `eval/reports/` (git-ignored).

## Contributing

Work test-first: write a failing test, see it fail, then write the code. Run
everything through `make` (`make test`, `make lint`, `make fmt`); tests and
tools exist only inside the Docker images. A new setting goes in
`backend/src/app/config.py`, in both `.env` example files, and in section 10 of
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). [AGENTS.md](AGENTS.md) has the
full set of rules, and `.cursor/rules/` has the conventions per area of the code.
Both apply to people and coding agents alike.

The design documents in `docs/` are the source of truth. When a change needs
the code to differ from them, update the documents in the same change.
